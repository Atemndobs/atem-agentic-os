# ATEM Positioning and First Article Brief

## Final Naming Decision

### Product
ATEM

### Category
Agentic OS

### One-line Positioning
ATEM - Agentic OS for session continuity across AI coding systems

## Core Concept

AI engineering is no longer limited by model capability.
It is limited by context fragmentation across tools.

ATEM defines the session control layer for multi-provider AI engineering.

Not an IDE.
Not an agent framework.
Not an orchestration runtime.

A control plane that keeps work coherent while tools change.

## Category Definition

Agentic OS is a system that:
- Persists task and session state
- Standardizes handoffs between agents
- Enforces workspace and repository boundaries
- Decouples execution from context

## First Article Concept

The article is not about ATEM.
It is about why AI engineering is breaking at the session layer.

## Article Structure

### 1) Hook
We're no longer bottlenecked by AI model quality.
We're bottlenecked by what happens when we switch between them.

Claude Code -> Codex -> Cursor -> local models.
Every switch resets context.

### 2) Business Problem
Impact:
- Duplicated reasoning
- Inconsistent outputs
- Engineering time wasted
- Fragile workflows

Teams are rebuilding context instead of shipping code.

### 3) Core Insight
AI coding is not a single-tool problem anymore.
It's a multi-provider coordination problem.

The failure point isn't execution.
It's session continuity.

### 4) Practical Observation
Observed in real systems:
- Multiple providers
- Repository boundaries
- Worktrees
- Sessions breaking

Every tool had its own memory.
None of them shared state.

### 5) Strategic Shift
AI adoption should move from:
- Better prompts
- Better models

to:
- Session state
- Handoff contracts
- Context persistence
- Task intent

### 6) Introduce ATEM
We built ATEM - an Agentic OS that standardizes session state across AI coding systems.

It doesn't run agents. It keeps them aligned.

### 7) Deeper Lesson
The system worked technically.
The failure was unclear task intent.

AI systems don't just need context.
They need structured intent.

### 8) Strategic Implication
Teams that win won't be the ones with the best models.
They will:
- Control context
- Define intent clearly
- Enforce boundaries
- Orchestrate across tools

### 9) Closing Question
If your team is already using multiple AI coding tools:
how are you maintaining session continuity between them?

Or are you still relying on copy-paste as your control plane?
